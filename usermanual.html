User Manual

A complete guide for day-to-day operation of the Hawk-Eye monitoring dashboard. No prior monitoring experience required.

Getting Started

After a successful installation, open your browser and navigate to http://localhost:8080. You will be greeted by the login page.

  1. Log InEnter your credentials. The default is admin / admin. Change your password immediately after your first login via the Admin settings.
  2. You're on the Live DashboardThis is the home screen. It shows real-time health and latency data for all configured targets. A green dot means a target is UP, red means it's DOWN.
  3. Configure your first targetIf no targets are shown, go to the Inventory page (top nav) to add targets, or ask your administrator to update checks.yaml.

Live Dashboard

The Live Dashboard provides a WebSocket-based real-time view of your entire monitored infrastructure. Data refreshes automatically without needing to reload the page.

Reading the Status Table

Each row represents a monitored target. The columns cover all monitoring layers simultaneously:

Column Check Type Description
Application / Target — The URL or hostname being monitored, with favicon icon
Tags — User-defined labels (e.g., Production, TSI, Shopping). Click to edit.
L7 Health (HTTP) health 🟢 Healthy / 🔴 Down — based on HTTP response code and retry logic
Latency latency Round-trip time in milliseconds. Shows first-byte time as sub-text.
DNS Resolution dns ✅ Resolved / ❌ Failed — DNS lookup status and server used
TCP Handshake tcp_metrics Time (ms) to establish a raw TCP connection to the target port
SSL/TLS Validity ssl_tls Days remaining until the TLS certificate expires. Shows warning if < 30 days.
Network Path traceroute Minimum hop count to reach the target (e.g., "0 Hops — Restricted by Docker")
Packet Loss traceroute Percentage of hops that did not respond. 0.0% = clean path.

Using the Search Bar

Type in the search bar (top of the page) to filter targets in real time. The filter applies to target names, IPs, and tags simultaneously. Press Esc to clear.

Using the Incident Summary

If any targets are DOWN, the dashboard will show an "Incident Summary" banner at the top with a count and links to open Grafana or Alertmanager for deeper investigation.

Inventory Page

The Inventory page is accessible from the top navigation bar. It provides a full list of all configured monitoring targets with their associated metadata.

Grouping Targets

Use the Group By dropdown (top right of the inventory) to organize targets:

  • None — a flat alphabetical list of all targets
  • Tags — groups targets by their assigned tags (e.g., all production targets together)
  • Name (Regex) — use a regular expression to group targets by naming pattern (e.g., ^api- groups all targets that start with "api-")

Alert Configuration

The Alerts → Config page allows you to view and edit Prometheus alerting rules that control when notifications are sent.

  • Select a target from the left sidebar to view its current alert rules
  • Click Edit to modify thresholds (e.g., alert if latency > 500ms for 5 minutes)
  • Changes are applied immediately via the Prometheus /-/reload API

Incorrect YAML syntax in alert rules will cause the Prometheus reload to fail. Always validate your YAML before saving.

Tagging & Grouping

Tags are stored in your browser's localStorage and can be applied or removed from the dashboard sidebar. They allow you to create logical groupings:

  • Tags like production, eu-west, database let you filter the dashboard to see only relevant targets
  • Multiple tags can be active simultaneously for complex filter queries
  • Tags are exported as part of the full configuration backup

Backup & Restore (Export / Import)

Hawk-Eye supports a one-click backup of the entire configuration, which can be restored on a new instance. This is useful for migrations, DR testing, or version-controlled config management.

Export Configuration

  1. Click "Export" in the top navigation barA progress notification will appear at the bottom right of the screen.
  2. A ZIP file will be downloadedNamed hawk-eye-full-config-YYYY-MM-DD.zip. Keep this file secure — it contains your alert thresholds and notification configurations.

Import Configuration

  1. Click "Import" in the top navigation barA confirmation dialog will warn you that existing configuration will be overwritten.
  2. Select your ZIP backup fileThe system will unpack the archive and load all configuration files.
  3. Services reload automaticallyPrometheus and Alertmanager will reload their configs within a few seconds. The dashboard will refresh.

Import will overwrite all current configuration files. Ensure you have an existing backup before importing an older one.

Incident Management

The All Incidents page (/incidents) provides a live, sortable view of every alert that Prometheus has triggered for your monitored targets.

Understanding the Incidents Table

ColumnDescription
SeverityCritical / Warning / Info — color-coded badge
StatusOpen (active) or Closed (resolved)
TargetThe monitored URL / host that triggered the alert
Rule / Group KeyThe Prometheus alerting rule name that fired
Opened TimeThe ISO 8601 timestamp when the alert first fired
DurationTime elapsed since the alert opened
DrilldownClick to open the full Incident Drilldown view for this alert

All incidents are persisted to localStorage under the key hawkeye_incident_history. They survive browser refreshes and accumulate over time for correlation purposes.

Incident Drilldown

Clicking Drilldown → on any incident opens the full Incident Drilldown view at /incident_drilldown?group=<key>. This view is modelled after enterprise NOC tools (e.g., HPE NNMi) and provides four contextual tabs:

  • General — Core incident metadata: severity, lifecycle state, assignee, description, origin check family, and total occurrence count.
  • Correlated Events — A filtered, sortable history of all previous similar incidents sharing the same Group Key.
  • Source Node Details — Network topology information for the monitored target node (hostname, IP, device type, management mode).
  • Diagnostics — Embedded troubleshooting actions: SSL certificate check, TCP port test, DNS resolution — all run live for the affected target.

The drilldown page supports deep-linking via the ?id= query parameter, allowing you to bookmark or share a specific historical occurrence of an incident.

Correlated Events

The Correlated Events tab inside the Incident Drilldown automatically aggregates every historical occurrence of the same alert group, giving you a complete pattern-of-failure timeline at a glance.

How the Correlation Engine Works

  1. Group Key MatchingIncidents are grouped by their Prometheus groupKey, or by ruleId::target if no group key exists.
  2. Priority SortingOpen (active) incidents are always promoted to the top of the list, regardless of timestamp. Within each status group, events are sorted newest-first.
  3. Section DividerA visual separator labeled Closed Incidents automatically appears between Open and Closed rows.
  4. Drilldown PivotingClicking any historical row reloads the entire drilldown context to that specific occurrence via ?id= — including the General, Timeline, and Diagnostics tabs.

Filtering & Sorting

Each column header in the Correlated Events table is independently sortable (click to sort ascending/descending, indicated by a caret icon) and has an inline text filter input for real-time row filtering by Incident ID, Severity, Time, or Status.

Open incidents render with a red-tinted row background and a pulsing LIVE indicator. The header badge also shows the count of currently active incidents in that group (e.g., 2 OPEN).

Endpoint Manager

The Endpoint Manager (/endpoints) enables distributed, federated Hawk-Eye monitoring across multiple remote Sparrow instances. It is accessible from Configuration → Endpoint Manager in the sidebar.

Registering a New Endpoint

  1. Fill in the registration formProvide a Name, Endpoint URL (e.g., http://10.x.x.x:8080), Region, Environment (Production / Staging / Development), Polling Interval, and Timeout.
  2. Test ConnectivityClick Test Connectivity before saving to validate the endpoint is reachable and measure latency.
  3. Save EndpointClick Save Endpoint. The backend immediately persists the record to endpoints_registry.json and regenerates the Prometheus file-based service discovery configuration (prometheus_sd_endpoints.yml).
  4. Prometheus picks it up automaticallyBecause Prometheus is configured with file_sd_configs pointing at the generated file, it begins scraping the new endpoint within the next polling cycle — no Prometheus restart required.

Active Endpoints Table

ColumnDescription
StatusUP / DOWN / DISABLED — updated by the async health-check worker pool

The Endpoint Manager table auto-refreshes every 5 seconds to reflect live health check results. Deleted endpoints are immediately removed from Prometheus service discovery.

Target Inventory — Endpoint Column

The Target Inventory page includes an Endpoint column that identifies which Sparrow instance discovered each monitored target. Locally monitored targets display a Local Instance badge. Targets from remote endpoints display their registered endpoint name.

AI Observability Assistant

The Hawk-Eye AI Assistant is an embedded observability copilot powered by your configured LLM backend (Gemini, Ollama, NVIDIA NIM, or OpenAI-compatible APIs). It is accessible via the floating AI button visible on every page.

Capabilities

  • Ask natural-language questions about your monitored targets (e.g., "Why is app.example.com slow?")
  • Fetch live Prometheus metrics, alert states, and incident history on demand
  • Perform SSL certificate checks, DNS resolution tests, and TCP port probes via tool calls
  • Summarise active incidents and recommend remediation steps
  • Query target latency trends and packet loss statistics from Prometheus

Configuring the LLM Backend

Edit observability_ai_assistant/config.py to set your preferred provider:

  • LLM_PROVIDER = "gemini" — Google Gemini via API key
  • LLM_PROVIDER = "ollama" — Local Ollama model (no API key required)
  • LLM_PROVIDER = "nvidia" — NVIDIA NIM cloud inference
  • LLM_PROVIDER = "openai" — Any OpenAI-compatible endpoint

The AI Assistant web API runs on port 5001 by default. Make sure it is running (python3 web_api.py) before using the assistant widget.

Troubleshooting Tools

The Troubleshooting page (/troubleshooting) provides a suite of real-time diagnostic tools you can run directly from the browser without needing shell access.

ToolWhat it does
SSL Certificate CheckConnects to the target host and retrieves the TLS certificate. Reports days-to-expiry, issuer, and validity status in real time from the backend (not simulated).
DNS Resolution TestResolves the hostname using the system resolver and reports the resolved IP address and lookup latency.
TCP Port ProbeAttempts a raw TCP connection to the specified port and reports reachability and handshake time.
HTTP Response ProbePerforms a full HTTP GET and displays the status code, redirect chain, and total response time.
TracerouteShows the network hop path from the Sparrow agent to the target (where ICMP is permitted).

Traceroute requires ICMP access. Inside Docker containers, raw ICMP is restricted — hop count may show as 0 with a note "Restricted by Docker".
